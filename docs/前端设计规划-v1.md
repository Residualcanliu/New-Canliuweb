# 个人网站 · 前端设计规划 v1

技术前提：前端 Next.js（App Router / TypeScript），后端 FastAPI 后置。本轮只解决前端视觉与体验。
核心视觉母题：纯黑场 → 纯白蝴蝶由左飞入中央 → 身后轨迹逐渐变白 → 抵达后画面缓缓展开。

---

## 0. 一句话方向

不要把它做成「三个动画（飞行 + 残影 + 开幕）拼在一起」，而要让它成为**一个动作**：
蝴蝶的飞行轨迹就是黑幕上的裂缝，轨迹变白 = 裂缝被烧穿，开幕 = 裂缝扩成视口。
这样观众记住的是一个隐喻（光从一个点撑开整个画面），而不是三段特效。

这条主线决定了后面所有技术选择，也是本方案与常见「粒子开场」的最大区别。

## 1. 视觉叙事脚本（分镜 + 时间轴）

推荐节奏：中速版 6.4s。括号内为快版 4.2s 的压缩点。

| 时间 | 画面 | 运动/缓动 |
|---|---|---|
| 0.00–0.80 | 纯黑，什么都不发生 | 刻意留白，建立"黑"的基准（快版 0.4s） |
| 0.80–3.60 | 白色蝴蝶从左缘外（x=-8%）沿一条 S 形缓升曲线飞向 (50%, 46%) | 入场 easeOutQuad → 中段近匀速 → 最后 0.8s power2.out 减速（快版合并为 1.8s） |
| 全过程 | 身后留下 1.5–24px 变宽、边缘羽化的轨迹；新写入的轨迹是 rgba(255,255,255,0.06)，约 0.5s 内"爬升"到纯白 | 视觉上像霜沿着它经过的地方蔓延 |
| 3.20–4.00 | 中央减速拍翅：频率 5Hz → 2.5Hz，幅度收小，身体上下浮动 3px | 告诉观众"它到了"，同时给换气口 |
| 4.00–4.20 | **0.2s 绝对静止** | 静止产生张力，这是整段的题眼，不要省 |
| 4.20–6.20 | 轨迹从"线"膨胀成"洞"：沿法线向两侧推开，24px → 180vmax；黑幕以轨迹为骨架裂开，裂口边缘保持有机毛边；整体 scale 0.98→1.0 | power3.inOut |
| 5.60–6.20 | 内容在洞内先以 blur 8px / opacity 0.6 / y+12 出现，再对焦到 0 | stagger 60ms |
| 6.20–7.00 | 黑幕消失，蝴蝶飞走或落在首屏锚点（见 D6），进入可滚动状态 | 结束后 0.8s 内必须有第二次内容动作（scroll cue 或标题错位归位），否则"死场" |

三条节奏档位（需你选，见 D2）：
- A 快 4.2s：适合作品集被快速浏览，回头率友好
- B 中速 6.4s：推荐，一次完整呼吸
- C 电影感 9s+：情绪最强，但第二次访问必须跳过

播放规则（建议直接定死）：sessionStorage 记录，同一会话只播一次；从 /work/[slug] 等深链落地时不播；prefers-reduced-motion 时降级为 0.6s 淡入。

## 2. 页面结构

路由（App Router）：

```
/                 开场 + 首页
/work             作品索引（网格 / 列表切换）
/work/[slug]      案例详情（问题 → 过程 → 结果）
/about            关于：长文 + 时间线 + 现在在做什么
/notes            笔记列表（MDX）
/notes/[slug]     笔记详情
/lab              可选：交互实验，展示技术上限
/404              彩蛋：蝴蝶找不到方向
```

首页分屏（极简 5 屏，滚动总长约 5 个视口）：

1. **Hero**：名字（衬线大字）+ 一句话定位 + 一个极简状态（当前在做什么 / 城市 / 可接洽）。布点必须落在开幕裂口的几何中心。
2. **Selected Work**：3–4 个案例，横向大留白，缩略图统一黑底白物，hover 时只做 1px 描边和位移，不做花哨放大。
3. **Capability / Stack**：一行技术图谱，可用"轨迹线"串联，是母题复用点。
4. **About 摘要**：150 字 + 入口。
5. **Notes 3 条 + Contact**：极简页脚，邮件直出，不做表单（除非后端同期上线）。

关于后端边界（本轮不实现，但会影响组件写法）：内容读取统一封在 `lib/content` 的一个 `ContentSource` 接口后面，当前实现读 MDX / 本地 JSON，后期换成 fetch FastAPI 只改一个文件，页面组件不动。

## 3. 组件划分

原则：内容全部是 Server Component（保证 HTML 里有字，SEO 与首屏），只有开场和少数交互是 Client 岛。

```
app/
  layout.tsx               server：字体、metadata、CSS 变量、<body> 底色 #000
  page.tsx                 server：输出完整首页内容 + 引入 IntroGate
  work/page.tsx 等          server

components/
  intro/
    IntroGate.tsx          client：是否播放、sessionStorage、reduced-motion、跳过按钮
    ButterflyCanvas.tsx    client：一块全屏 canvas，三层合成（轨迹 / 蝴蝶 / 黑幕）
    Butterfly.tsx          纯 SVG，无依赖，props: wingPhase, tilt, blur
    useIntroTimeline.ts    GSAP timeline 编排，导出 phase: idle|flying|arriving|opening|done
    TrailBuffer.ts         与框架无关的类，可单测（采样、老化、膨胀）
  hero/      HeroName / HeroTagline / ScrollCue
  work/      WorkGrid(server) / WorkCard / WorkMeta
  notes/     NoteList / NoteItem
  chrome/    Nav(client，路由过渡用) / Footer / Hairline
  typography/ Prose / SectionHeading

lib/
  motion/    easings.ts / timeline.ts / useReducedMotion.ts
  content/   source.ts（MDX → 日后 FastAPI）
  api/       client.ts（预留 NEXT_PUBLIC_API_BASE）
```

状态管理：开场只有 5 个状态，用 `useReducer` 显式状态机即可，不引 xstate。

## 4. 动画实现思路（三层）

### L0 轨迹层：这是整个方案的技术难点，也是唯一需要提前定方案的地方

「逐渐变白」本质是 **每个像素带 age**，颜色 = mix(#0a0a0a, #fff, f(age))。三种做法，成本差一个数量级：

| 方案 | 实现 | 效果上限 | 成本 | 结论 |
|---|---|---|---|---|
| A. SVG 描边 | 一条 stroke 路径 + stroke-dashoffset 生长，外挂 blur + 多层描边模拟羽化 | 干净、锐利，但"变白"只能靠整体透明度，做不出老化的层次 | 最低，1 天 | 保守可用 |
| B. Canvas 2D | 维护轨迹点数组，每帧按 age 重绘整条带状路径（分段透明 + 变宽），叠加 2 次柔化 | 能达到 85% 的期望，60fps 稳 | 中，2–3 天 | **推荐起点** |
| C. WebGL | ping-pong FBO 存 age 纹理，fragment shader 一次出图；同一张纹理直接当黑幕遮罩 | 最高，可加噪点、色散、体积极光 | 高，1–2 周 | 若选粒子/3D 蝴蝶则必选 |

建议：先做 B，把 B 的轨迹纹理抽象成一张"揭示图"（0–1 的 alpha 图），开幕时直接用它做黑幕遮罩，同一张图从"装饰"变成"功能性遮罩"——这也是把它做成一个动作的技术落点。若后期要升级 C，只替换 TrailBuffer 的实现，上游 timeline 不变。

### L1 蝴蝶本体

- 形态：两只翅膀 SVG path + 身体 1px 线 + 两根触角。用 `scaleX` 制造扇动错觉（透视靠 scaleX 而非 3D 旋转，成本低且侧面看更自然）。
- 路径：手绘一条 Catmull-Rom 曲线 → 采样成点表；或 GSAP `MotionPathPlugin` 沿 SVG path 走。手绘曲线更容易调出"犹豫感"（真实蝴蝶不是匀速直线）。
- 朝向：用相邻帧切线算角度，加 6–10° 的惯性滞后（follow-the-leader），避免"贴死在路径上"的机械感。
- 拍翅与速度耦合：高速段大拍 5–6Hz，减速段降到 2.5Hz 并出现 1–2 次"滑翔停桨"（0.2s 不扇翅），这是让观众觉得"它是活的"的关键细节。
- 自身必须恒纯白 #FFF：不要给它加发光、阴影、渐变，唯一允许的是运动模糊（尾随 2 帧的半透明残像）。它的"亮"来自周围的黑，不来自特效。

### L2 开幕：四个方案与取舍

- **O1 对开幕布**：左右两块黑幕滑开。稳、实现最易，但轨迹沦为装饰，因果断裂。
- **O2 沿轨迹裂开（推荐）**：轨迹即裂缝，白色描边膨胀成面，边缘用 feTurbulence / fbm noise 保持毛边，同时整体 scale 0.98→1.0 制造纵深。三个元素合成一个动作，记忆点最强；代价是遮罩实现复杂度最高。
- **O3 光圈 iris**：轨迹末端作圆心，圆形扩散。最简单，但视觉语言很通用，容易被认成模板。
- **O4 溶解粒子**：轨迹白点扩散成雾，雾散露出内容。梦幻，但与黑白极简气质容易打架，且性能重。

推荐 O2。若工期紧，O3 作为降级方案保留在代码里（同一 timeline，换一个 mask 生成器即可）。

### L3 内容衔接

- 开幕后需要"落点"：裂口最终要收敛成矩形视口，名字正好在裂口中心，观众视线不需要重新寻找。
- 母题复用（避免开场独美、内页平庸）：section 之间的分隔线采样自同一条蝴蝶曲线的不同片段；滚动进度条就是这条线被重新"画"出来。比让蝴蝶到处飞克制得多。
- 色彩反转的隐患：全站纯黑时，开场的白是画面唯一的高光，会把内容衬得"灰"。两个解法见 D5。

## 5. 关键技术选型

| 关注点 | 选择 | 理由 / 备选 |
|---|---|---|
| 框架 | Next.js 15 App Router + TS | RSC 保证内容在 HTML；动画层是唯一 client 岛 |
| 样式 | Tailwind v4 + CSS 变量 | 黑白体系只需约 12 个 token（bg / fg / hairline / muted / 3 档字级） |
| 时间轴 | **GSAP 3**（现全部插件免费，含 ScrollTrigger / MorphSVG / SplitText） | 开场是"0.1s 级多元素编排"，GSAP timeline 仍是最顺手的工具，可 seek 可反向可调试 |
| 布局/滚动交互 | Motion（framer-motion 后继，motion/react） | layout 动画、whileInView、手势更强，与 GSAP 分工：GSAP 管开场，Motion 管内页 |
| 画面渲染 | Canvas 2D 起步；若要粒子/3D 蝴蝶 → three + @react-three/fiber + 自定义 shader | 见 L0 表格 |
| 有机边缘 | SVG feTurbulence 或 shader fbm | 决定裂口是"塑料"还是"烧穿" |
| 字体 | 拉丁 Geist / Inter Tight；中文思源黑或思源宋 | 建议无衬线做界面、衬线只给名字与一句话，形成两级气质 |
| 内容 | MDX + frontmatter，封在 ContentSource 接口后 | 后期换 FastAPI 只改一个文件 |
| 部署 | Vercel；FastAPI 独立服务，预留 NEXT_PUBLIC_API_BASE | 同域反代可避免 CORS |
| 性能预算 | 开场相关 JS ≤ 150KB gz；DPR 上限 2；移动端轨迹采样降频；canvas 为 fixed + pointer-events:none + aria-hidden | LCP 元素必须是 hero 文本，不能是 canvas |
| 可访问性 | reduced-motion 走 0.6s 淡入；提供"跳过开场"；noscript 直出内容；开场期间仍可 Tab | 这是个人网站最容易被忽略的失分项 |

## 7. 需要你确认的决策点

**D1 轨迹的语义（最影响后续）**
A 留痕：轨迹是"记忆/雾"，慢慢亮起然后保留。→ 开幕只能另做（O1/O3）。
B 撕裂：轨迹是"裂缝"，黑幕被它烧穿。→ 开幕 = 轨迹膨胀（O2），三者合一。
建议 B。

**D2 节奏与播放次数**
A 4.2s 快 / B 6.4s 中（推荐）/ C 9s+ 电影感。另需确认：每次访问都播、每会话一次（推荐）、还是只有首次访问播。

**D3 蝴蝶的具象度**
A 写实剪影（翅膀有细节，最"生物"）/ B 几何折纸（棱角，最"设计"）/ C 单线描（极简，最"高级"）/ D 点阵粒子（最"技术"，成本最高）
建议 C 或 B，写实剪影在纯黑场里容易显廉价。

**D4 开幕方式**
O1 对开 / O2 沿轨迹裂开（推荐）/ O3 光圈 / O4 溶解。若选 D1-A，则只能在 O1 与 O3 中选。

**D5 开幕后的世界观（最容易做拧的地方）**
A 全站纯黑：白只属于开场和文字，靠字重与 1px 描边撑住层次。
B 开幕后翻成纸白底黑字：开场是网站本体的负片，记忆点最强，但违背"纯黑"诉求。
C 混合：首页纯黑，案例详情页纸白（阅读更舒服，但风格会断层）。
建议 A，且用"大字号 + 大留白"补足层次；若你更看重记忆点，选 B。

**D6 蝴蝶是否常驻**
A 只在开场出现，之后消失（最克制，推荐）
B 滚动时沿分隔线再次出现（母题复用，成本中）
C 作为光标伴侣（有性格，但容易腻，移动端无效）

**D7 语言与字体气质**
中文 / 英文 / 双语；冷峻无衬线（工程师感）还是衬线文学感（作者感）。这决定名字那一行的排法。

**D8 移动端**
竖屏下轨迹是否改为纵向（从上方飞入）？还是保留横飞但缩短行程？移动端是否直接砍掉开幕只留 1s 淡入（最稳）。

**D9 后端时间点**
FastAPI 是否同期上线？若同期，作品与笔记需要 CMS 化的内容模型；若后置，现在全部走 MDX，接口层留桩。

## 9. 已确认参数（2026-10-27 定稿）

D1-B 轨迹即裂缝 ／ D2-A 快节奏 4.2s ／ D3-BCD 三版同时出 ／ D4-O2 沿轨迹裂开 ／ D5-A 全站纯黑 ／ D6-A 蝴蝶仅开场 ／ D7 双语（CN/EN 切换）／ D9 后端后置（先全 MDX，接口留桩）

### 9.1 快速版时间轴（4.2s）

| 时间 | 事件 | 缓动 / 参数 |
|---|---|---|
| 0.00–0.30 | 纯黑基准 | 静止 |
| 0.30–1.90 | 从左缘外飞至中央 (50%, 46%) | 入场 easeOutQuad → 末 0.5s power2.out |
| 全程 | 轨迹写入 1.6→10px 宽度；年龄映射：age 0–0.45s 内由 opacity 0.04 爬到 1.0 | age→white 用 smoothstep |
| 1.90–2.40 | 抵达收翅：拍翅 5Hz → 2.5Hz，scaleX 压到 0.72 | 0.5s |
| 2.40–2.60 | 绝对静止 | 0.2s，不要省 |
| 2.60–3.80 | 轨迹沿法线膨胀成开口，缝合线成为断口 | power3.inOut |
| 3.70–4.10 | 内容对焦：blur 8→0 / opacity 0.6→1 / y 12→0，stagger 45ms | 与裂开重叠 0.1s |
| 4.10–4.40 | 黑幕退净，蝴蝶已离场，残迹转为分隔线 | 进入可滚动 |

### 9.2 移动端规则（D8 我方定的）

- 轨迹改纵向：从上方外飞入，落点仍是屏幕中线偏上 8%。
- 总时长压到 3.2s，轨迹采样点减半（每 3px 一个点）。
- DPR 上限 1.5；粒子版（D）在移动端降级为虚线描边版（C）。
- 低端机（deviceMemory ≤ 4）直接跳过开场，0.6s 淡入。

### 9.3 已知风险：D5-A 的隐藏矛盾

黑幕裂开后，里面还是黑的——开幕感完全靠「撕裂边缘的白」+「内容自身的白色笔画」承载，没有常见的明暗反差可用。三条对策必须同时上：

1. 撕裂边缘必须是毛边（feTurbulence 或 fbm noise），否则像圆形光圈动画；
2. 开口内部给一档极低的提亮（#080808–#0C0C0C），让「已经打开」这件事可被感知；
3. 内容第一批元素（名字 / hairline）在开口内先以 30% 透明度出现，制造"光从缝里漏出来"的错觉。

若最终觉得开幕不够"炸"，唯一不破坏 D5-A 的加法是：开口瞬间整页做一次 0.98→1.0 的极缓 scale（3% 都不到），靠运动而非亮度制造纵深。

### 9.4 蝴蝶本体：改用剪影资产 + 程序化派生

手绘矢量的俯视蝴蝶（朝向观众）被否掉，纯 90° 侧视又会在 110px 尺度上读成"叶片"。定稿方案：

1. 用图像模型出一张**侧后方 3/4 视角、朝右飞**的纯白剪影（源文件 `个人网站/bfly-solid.png`）。
2. 由它程序化派生三种笔触，保证形态完全一致：**实心**（bfly-solid）/ **轮廓线**（原图减腐蚀，bfly-line）/ **点描**（轮廓采样点 + 内部疏点，bfly-dots）。阈值 200 顺带去掉水印，导出透明 PNG。
3. 实现阶段：这三张先作为位图资产接入（`/public/brand/`），web 端用 `<img>` + CSS 混合即可；若要无损放大，再描一次矢量（约 1 小时工作量），形态不用重画。

配套调整：轨迹终点不再落在身体中心，而是收到身体后缘并做 0.25s 渐隐——否则线稿版会出现"杆子穿过蝴蝶"的错觉。

### 9.5 定稿（2026-10-27）
